# End-to-End Example: Circom Multiplier (`Multiplier2`) to Stellar Testnet

This example walks through taking a Circom 2.0 circuit (`c <== a * b`), converting its `snarkjs` Groth16 BN254 artifacts into the **Astrolabe Canonical Format (`acf/0.1`)**, generating a Soroban verifier contract, verifying locally against the Soroban host simulator, and deploying and verifying on **Stellar Testnet (Protocol 25+)**.

---

```text

├── README.md                  # This walkthrough
├── circuit/
│   ├── multiplier2.circom     # Circom 2.0 circuit: c <== a * b (public [a])
│   └── input.json             # Sample input: {"a": "3", "b": "11"} -> c = 33
├── artifacts/

cargo run -p astrolabe-cli -- doctor
```

*(Pass `--offline` if you are working without internet access.)*

## 2. Understand the Circuit and Signal Ordering

Examine [`circuit/multiplier2.circom`](circuit/multiplier2.circom):

```circom
pragma circom 2.0.0;

template Multiplier2() {
    signal input a;
    signal input b;
    signal output c;

    c <== a * b;
}

component main {public [a]} = Multiplier2();
```

- **Private witness:** `b = 11` (never leaves the prover; never included in public artifacts).
- **Public input:** `a = 3`.
- **Public output:** `c = 33`.
- **Signal ordering (`spec/spec.md` Section 4.3):** `snarkjs` always emits **public outputs first, then public inputs** in circuit declaration order. Therefore [`artifacts/public.json`](artifacts/public.json) contains:
  ```json
  [
   "33",
   "3"
  ]
  ```
  where `s_0 = 33` (`0x...21`) and `s_1 = 3` (`0x...03`), and the verification key has `n_ic = n_public + 1 = 3` `G1` points.

## 3. Export `snarkjs` Artifacts to ACF (`astrolabe export`)

Pre-generated public `snarkjs` artifacts are included in [`artifacts/`](artifacts/) so you can run the pipeline immediately.

### Export as raw ACF hex (`acf-hex`)

```bash
cargo run -p astrolabe-cli -- export \
  --proof examples/circom-multiplier/artifacts/proof.json \
  --vk examples/circom-multiplier/artifacts/verification_key.json \
  --public examples/circom-multiplier/artifacts/public.json \
  --format acf-hex \
  --out-dir examples/circom-multiplier/artifacts
```

This validates every field element (`< p` or `< r`), curve point (`G1` on `y^2 = x^3 + 3`, `G2` on the twist curve), and `G2` prime-order-`r` subgroup membership, converts `G2` `Fp2` coordinates from `snarkjs` `[c0, c1]` into CAP-0074 `be32(c1) || be32(c0)` order, and writes:

- `proof.hex` (`256` bytes = `512` hex chars: `A || B || C`)
- `vk.hex` (`644` bytes = `1288` hex chars: `alpha_g1 || beta_g2 || gamma_g2 || delta_g2 || be32_u32(3) || IC[0..3]`)
- `public.hex` (`64` bytes = `128` hex chars: `be32(33) || be32(3)`)

### Export ready-to-run `stellar contract invoke` arguments (`soroban-args`)

```bash
cargo run -p astrolabe-cli -- export \
  --proof examples/circom-multiplier/artifacts/proof.json \
  --public examples/circom-multiplier/artifacts/public.json \
  --format soroban-args
```

## 4. Verify Locally in Soroban Host Simulation (`astrolabe verify`)

Before building or deploying any WASM, verify the proof locally using the exact Soroban Protocol 25+ BN254 host functions (`bn254_g1_mul`, `bn254_g1_add`, `bn254_multi_pairing_check`):

```bash
cargo run -p astrolabe-cli -- verify \
  --proof examples/circom-multiplier/artifacts/proof.json \
  --vk examples/circom-multiplier/artifacts/verification_key.json \
  --public examples/circom-multiplier/artifacts/public.json
```

Expected output:

```text
=== Astrolabe Local Verifier (Soroban Host Simulation) ===
✓ Proof verification SUCCEEDED!
  Public inputs count: 2
  Pairing check: VALID (product in GT is identity)
```

## 5. Generate, Test, and Build the Soroban Verifier Contract

### Generate the contract source (`astrolabe gen-verifier`)

[`contract/src/lib.rs`](contract/src/lib.rs) was generated with:

```bash
cargo run -p astrolabe-cli -- gen-verifier \
  --vk examples/circom-multiplier/artifacts/verification_key.json \
  --mode baked \
  --name MultiplierVerifier \
  --out examples/circom-multiplier/contract/src/lib.rs \
  --force
```

In `baked` mode, the 644-byte ACF verification key is embedded as a `pub const VK_BYTES: [u8; 644]` array in contract bytecode, avoiding ledger storage reads on every verification call. (Use `--mode stored` if you want an admin-upgradable verification key in instance storage.)

### Run the contract test suite

[`contract/tests/contract_test.rs`](contract/tests/contract_test.rs) tests:
1. Baked `VK_BYTES` matches `artifacts/verification_key.json` byte-for-byte.
2. Valid proof with `public = [33, 3]` returns `Ok(true)`.
3. Wrong public signal `[34, 3]` is rejected with `VerifierError::InvalidProof` (`ERR_INVALID_PROOF`).
4. Non-canonical scalar `s_0 = r` is rejected before `Bn254Fr` conversion with `VerifierError::NonCanonicalField` (`ERR_NON_CANONICAL_FIELD`).
5. Wrong public-input count `[33]` is rejected with `VerifierError::PublicInputCount` (`ERR_PUBLIC_INPUT_COUNT`).

```bash
cargo test -p multiplier-verifier
```

### Build the optimized Soroban WASM

```bash
stellar contract build --manifest-path examples/circom-multiplier/contract/Cargo.toml
```

This produces `target/wasm32v1-none/release/multiplier_verifier.wasm`.

## 6. Deploy and Verify on Stellar Testnet

### Step 6.1: Create and fund a Testnet identity

```bash
stellar keys generate --global alice --network testnet --fund
```

### Step 6.2: Deploy the verifier contract

```bash
CONTRACT_ID=$(stellar contract deploy \
  --wasm target/wasm32v1-none/release/multiplier_verifier.wasm \
  --source alice \
  --network testnet)
echo "Deployed MultiplierVerifier at: $CONTRACT_ID"
```

### Step 6.3: Verify the proof on Stellar Testnet

Use `astrolabe verify` with `--contract-id` (omit `--source` for a free read-only RPC simulation, or pass `--source alice` to submit a live on-chain transaction):

```bash
# Read-only RPC simulation on Testnet:
cargo run -p astrolabe-cli -- verify \
  --contract-id "$CONTRACT_ID" \
  --network testnet \
  --proof examples/circom-multiplier/artifacts/proof.json \
  --public examples/circom-multiplier/artifacts/public.json

# Or submit a signed transaction on Testnet:
cargo run -p astrolabe-cli -- verify \
  --contract-id "$CONTRACT_ID" \
  --network testnet \
  --source alice \
  --proof examples/circom-multiplier/artifacts/proof.json \
  --public examples/circom-multiplier/artifacts/public.json
```

## 7. Optional: Regenerate `snarkjs` Artifacts from Scratch

> **Security Warning:** The commands below run an ephemeral development Powers-of-Tau and Phase 2 ceremony for local testing only. **Never use a self-generated single-party ceremony in production** — anyone who knows the ceremony randomness ("toxic waste") can forge arbitrary proofs. Production deployments must use a multi-party ceremony (such as the Hermez / Perpetual Powers of Tau `.ptau` plus a multi-party Phase 2 `.zkey` ceremony).

If you have `circom` (`2.2.3+`) and `snarkjs` (`0.7.6+`) installed and want to compile [`circuit/multiplier2.circom`](circuit/multiplier2.circom) and generate a fresh proof in a temporary directory:

```bash
TMP_WORK=$(mktemp -d)
circom examples/circom-multiplier/circuit/multiplier2.circom --r1cs --wasm -o "$TMP_WORK"

# Compute witness in temporary directory (never commit .wtns files)
node "$TMP_WORK/multiplier2_js/generate_witness.js" \
  "$TMP_WORK/multiplier2_js/multiplier2.wasm" \
  examples/circom-multiplier/circuit/input.json \
  "$TMP_WORK/witness.wtns"

# Ephemeral development ceremony (TEST ONLY - NOT FOR PRODUCTION)
snarkjs powersoftau new bn128 8 "$TMP_WORK/pot8_0000.ptau"
snarkjs powersoftau contribute "$TMP_WORK/pot8_0000.ptau" "$TMP_WORK/pot8_0001.ptau" \
  --name="Dev Test" -e="astrolabe-dev-test-entropy"
snarkjs powersoftau prepare phase2 "$TMP_WORK/pot8_0001.ptau" "$TMP_WORK/pot8_final.ptau"
snarkjs groth16 setup "$TMP_WORK/multiplier2.r1cs" "$TMP_WORK/pot8_final.ptau" "$TMP_WORK/multiplier2_0000.zkey"
snarkjs zkey contribute "$TMP_WORK/multiplier2_0000.zkey" "$TMP_WORK/multiplier2_final.zkey" \
  --name="Dev Phase2" -e="astrolabe-dev-phase2-entropy"

# Export public verification key and generate proof
snarkjs zkey export verificationkey "$TMP_WORK/multiplier2_final.zkey" "$TMP_WORK/verification_key.json"
snarkjs groth16 prove "$TMP_WORK/multiplier2_final.zkey" "$TMP_WORK/witness.wtns" \
  "$TMP_WORK/proof.json" "$TMP_WORK/public.json"

# Confirm off-chain with snarkjs, then verify with Astrolabe
snarkjs groth16 verify "$TMP_WORK/verification_key.json" "$TMP_WORK/public.json" "$TMP_WORK/proof.json"
cargo run -p astrolabe-cli -- verify \
  --proof "$TMP_WORK/proof.json" \
  --vk "$TMP_WORK/verification_key.json" \
  --public "$TMP_WORK/public.json"

# Clean up all toxic waste and witness files
rm -rf "$TMP_WORK"
```
